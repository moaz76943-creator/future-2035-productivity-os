# Localization guide

The app's texts live in one ARB file per language: `lib/l10n/app_<code>.arb`. English
(`app_en.arb`) is the template and carries each text's description. The tools find the
languages from these files, so nothing else keeps a language list for them.

| Task | Command |
|---|---|
| Add or change a text in every language | `python3 tool/l10n_add_keys.py spec.json` |
| Edit one language in a file (or hand it to a translator) | `python3 tool/l10n_export.py ar` → edit `build/l10n/ar.json` → `python3 tool/l10n_import.py ar build/l10n/ar.json` |
| Remove texts no longer shown | `python3 tool/l10n_remove_keys.py key1 key2` |
| Add a language | `python3 tool/l10n_add_language.py de "Deutsch"` (see below) |
| After any of these | `flutter gen-l10n && python3 tool/gen_l10n_custom.py && python3 tool/check_l10n.py` |

`spec.json` for `l10n_add_keys.py` (every language is required):

```json
{"guardTitle": {"meta": {"description": "Where it shows"},
                "en": "Distraction guard", "ar": "حارس التشتت", "...": "..."}}
```

Placeholders go in `meta.placeholders` (`{"count": {"type": "int"}}`) and use ICU plurals:
`{count, plural, =1{1 card} other{{count} cards}}`.

## Adding a language

```
python3 tool/l10n_add_language.py tr "Türkçe"
```

It creates `app_tr.arb` (English to translate), `android/.../res/values-tr/*_strings.xml`
(home widgets, guard, Quick Settings tile), the `AppLocales.all` entry and `build/l10n/tr.json`.
Translate that file, import it, translate the Android files, then run the checks.
`check_l10n.py` lists every text still in English and fails until the language is complete:

- every key present, same placeholders, valid plurals for the language (CLDR categories in
  `tool/l10n_common.py`; add the language there first if the tool asks);
- registered in `AppLocales.all`, right-to-left set in step (`AppLocales.rtlLanguages` and
  `RTL` in `tool/l10n_common.py`), Android strings with the same names as `values/`;
- no Hebrew, Western digits only, no flags.

`test/unit/l10n/custom_words_test.dart` checks that every language loads with Material and
Cupertino texts. Fonts: Latin, Cyrillic and Greek (Manrope), Arabic (Readex Pro), Devanagari
(Noto) and CJK (system) are covered; another script needs a font in `assets/fonts/`, its
licence in `THIRD_PARTY_LICENSES.md`, and a line in `AppFonts`
(`lib/core/design_system/app_theme/lux_colors.dart`).

## The user's own wording

Settings → Rename words lets the user change any plain text of the app (texts with numbers
or names inside stay translated). It is a layer over the translations:
`lib/l10n/custom/custom_words.dart` plus `custom_l10n.g.dart`, generated by
`tool/gen_l10n_custom.py` from the generated `AppLocalizations`, so new texts and new
languages need no extra work. The words are stored per language in the settings store
(key `l10n.custom`) and so are part of backups. Notifications, the home widget, app icon
shortcuts and the guard's pause screen use them too.
